# Deviation log

Every place where genhttp-kt differs from GenHTTP *in spirit or behavior* is listed here with its reason.

| Area | Deviation | Reason |
|------|-----------|--------|
| Naming | Interfaces drop the `I` prefix; factory clashes resolved via companion extensions, implementation clashes via descriptive prefixes | Kotlin convention (decided by the maintainer) |
| Naming | `Async` suffix dropped, methods are `suspend` | Kotlin coroutine convention |
| Generators | `[MemoryView]` source generator replaced by the `MemoryView` base class; the views (`ByteString`, `ContentType`, ...) are classes instead of structs and compute their hash on first use | No source generators needed on the JVM; no user-defined value types on the JVM (Kotlin value classes wrap a single value and are boxed when used as keys or through interfaces) |
| Engines | Kestrel is not ported; the ioxide engine is ported on ioxide's own Kotlin runtime (`Engine/Ioxide`, `org.genhttp.engine.ioxide.Host`, packages `genhttp-core-ioxide`/`genhttp-full-ioxide`, Linux only like upstream) and, by intent, as the portable Netty engine (`Engine/Netty`, `org.genhttp.engine.netty.Host`, packages `genhttp-core-netty`/`genhttp-full-netty`); `ServerEngine` contains `Internal`, `Netty`, `Ioxide` and `Custom` | Kestrel is .NET specific; ioxide ships a Kotlin port of its runtime, Netty is the JVM counterpart of ioxide on every platform (one event loop per core, sockets registered once, handlers executed on the loop that owns the connection) |
| Netty engine | `EngineOptions` are Netty specific: `EventLoopOptions(count, transport)` replaces `ReactorOptions` (ring entries, receive buffers and slots), `Transport` (`Auto`, `Epoll`, `IoUring`, `Nio`) is new; `TcpTransportOptions` keeps `handshakeTimeout`, `cipherSuites`, `cipherList`, `listenBacklog`, `idleTimeout` and `sendTimeout` (timeouts as `Duration`, disabled by default like upstream) and gains `tlsProvider` (`Auto`, `OpenSsl`, `Jdk`); kTLS, write slab, pool and zero copy options as well as `QuicTransportOptions`/`Http3Options` do not exist; `onReactorStart` → `onEventLoopStart` receiving Netty's `EventLoop` | The options tune the io_uring runtime of ioxide, which Netty replaces |
| Netty engine | HTTP/1.1 only (plain and TLS, keep-alive, pipelining, upgrades); HTTP/2, HTTP/3 and the native file path (`ioxide.file`) are not ported yet | Scope of the first version (see `docs/specs/netty-engine.md`) |
| Netty engine | Request bodies are buffered completely before the handler is invoked (Content-Length bodies and chunked bodies up to the terminating chunk, at most 512 MB, larger bodies are answered with 413) | `RequestBody.asStream()` returns a blocking `InputStream`, which cannot wait for data on the event loop that has to deliver it |
| Netty engine | The response of an upgrade is written on a virtual thread; the stream returned by `Request.upgrade()` implements `SuspendingInput`, content that uses it (the websockets module) moves to the event loop of the connection and reads without blocking, other content (e.g. the websocket tunnel of the reverse proxy) reads blocking on the virtual thread; writes on the loop (and of other event loops) never wait, the driver and `readSuspending` wait while the channel is not writable instead; writes of other threads are flushed immediately and wait while the channel is not writable | The upgraded stream is a blocking `InputStream`, upstream reads it from a `PipeReader` on the reactor |
| Netty engine | TLS is terminated by Netty's `SniHandler` with OpenSSL (BoringSSL from netty-tcnative, natives for Linux, macOS and Windows) or the JDK provider (`TcpTransportOptions.tlsProvider`): the certificate is selected per host through the `CertificateProvider` (one `SslContext` per certificate), any `CertificateValidator` works with both providers (no trust anchors required, the `ClientCertificateAuthenticationTests` special case of ioxide does not apply), the handshake timeout is `TcpTransportOptions.handshakeTimeout`; `cipherList` (TLS 1.2) applies to both providers, `cipherSuites` (TLS 1.3) only to the JDK provider (BoringSSL does not allow to configure them, a warning is logged); certificates cannot be reloaded at runtime (`ReloadCertificates`) | Providers as offered by Netty; the certificate provider is asked per handshake anyway |
| Netty engine | Endpoints keep the semantics of the internal engine: dual stack per endpoint (ioxide requires the same mode for all endpoints), several endpoints may share a port on different addresses (ioxide matches connections to endpoints by port and refuses this), IPv4 clients of IPv6-only endpoints are closed after the TCP connect (with io_uring, which only creates sockets of the preferred family, IPv6 clients of IPv4-only endpoints as well); with epoll and io_uring every loop binds its own socket (`SO_REUSEPORT`) after the port has been probed without `SO_REUSEPORT`, with NIO one socket accepts for all loops | Netty cannot set `IPV6_V6ONLY` portably either; sockets sharing a port with `SO_REUSEPORT` would not detect a port that is already in use |
| Netty engine | The `Server` header is `GenHTTP/<version>` (ioxide: `ioxide-genhttp`); a `Listening on` line is logged per endpoint, the shutdown is not logged; the whole state of a connection (request, reader with its buffer, writer) is pooled per event loop (at most 1024, like the request pool per reactor of ioxide), there is no thread hop warning | Shared `ServerHeader` and logging of the internal engine; the dispatcher always returns coroutines to their loop |
| Netty engine | Unterminated request headers that exceed the header size limit (1 MB) are rejected with 431 instead of waiting for the end of the header | Connections have no read timeout by default, the buffer would grow without bounds |
| ioxide engine | `ReactorOptions` has no `Incremental`, `TcpTransportOptions` has no `WriteOverflow` (the write slab always grows) and no `ZeroCopySend`, `QuicTransportOptions` and `Http3Options` do not exist; `TcpTransportOptions` gains `tlsProvider` (`Auto`, `BoringSsl`, `Jdk`) | ioxide's Kotlin port is the TCP runtime with TLS: it has no incremental buffer rings, overflow strategies, zero copy sends or QUIC |
| ioxide engine | HTTP/1.1 only (plain and TLS, keep-alive, pipelining, upgrades); HTTP/2, HTTP/3, the native file path (`ioxide.file`) and `IoxideReactor.Current` (`GenHTTP.Api.Ioxide`, the reactor is passed to `onReactorStart`) are not ported yet | Scope of ioxide's Kotlin port and of the first version (see `docs/specs/ioxide-engine.md`) |
| ioxide engine | TLS is terminated by BoringSSL through ioxide (with optional kernel TLS) for endpoints with one certificate for every host and no client certificates, by the JDK for the others (`TcpTransportOptions.tlsProvider`, `Auto` by default, an explicit `BoringSsl` refuses the others); with the JDK, certificates are selected per host through the `CertificateProvider` and any `CertificateValidator` works (no trust anchors required, the `ClientCertificateAuthenticationTests` special case of ioxide does not apply), `cipherList` takes IANA names; the certificate providers of upstream (`FileCertificateProvider`, `HostCertificateProvider`, `IMutualTlsValidator`) and `ReloadCertificates` do not exist | ioxide's Kotlin port does not select certificates per host, validate client certificates or rotate certificates yet |
| ioxide engine | Request bodies are buffered completely before the handler is invoked (like the Netty engine); the response of an upgrade is written on a virtual thread, the stream returned by `Request.upgrade()` implements `SuspendingInput` (websockets read on the reactor), writes of other threads wait until the reactor has sent them, writes of other reactors do not wait | `RequestBody.asStream()` and the upgraded stream are blocking `InputStream`s, upstream reads them from a `PipeReader` on the reactor |
| ioxide engine | The `Server` header is `GenHTTP/<version>` (upstream: `ioxide-genhttp`); a `Listening on` line is logged per endpoint, the shutdown is not logged; the whole state of a connection (request, reader with its buffer, writer) is pooled per reactor (at most 1024), there is no thread hop warning; the address of an endpoint is not applied (as upstream), which is logged as a warning | Shared `ServerHeader` and logging of the other engines; the dispatcher always returns coroutines to their reactor |
| ioxide engine | Ports are probed without `SO_REUSEPORT` before the reactors bind them (`BindingException` if a port is in use, a free port for port 0), and stopping a server waits until its ports can be bound again | Sockets sharing a port with `SO_REUSEPORT` would not detect a port that is already in use; the kernel releases the listeners of a closed ring asynchronously |
| ioxide engine | A client that keeps sending requests or frames without reading the answers is disconnected once its receive queue overflows (`recvQueueEntries`), instead of being pushed back by TCP (like upstream) | ioxide receives with multishot receives into the buffers of its reactor, which do not stop while a connection does not read |
| ioxide engine | Unterminated request headers that exceed the header size limit (1 MB) are rejected with 431 instead of waiting for the end of the header; connections terminated with kernel TLS wait (up to 10 seconds) until the send queue of their socket stayed empty for 50 ms before they are closed | Connections have no read timeout by default; the kernel passes the records it encrypted to TCP asynchronously, the FIN sent when ioxide releases the connection would overtake them |
| ioxide engine | ioxide's Kotlin port is kept in the repository (`Ioxide/`, artifact `ioxide-kt`, commit in `upstream.properties`) with dual-stack listeners added (`ServerConfig.dualStack`, as in ioxide's C# runtime) | The Kotlin port is not published yet and did not bind dual-stack listeners |
| Adapters | `GenHTTP.Adapters.AspNetCore` is not ported | ASP.NET Core does not exist on the JVM |
| I/O | `Stream` → `InputStream`/`OutputStream`, `IBufferWriter` → `WritableByteChannel`, `PipeReader` → `InputStream` | JVM standard types, usable from coroutines because connections run on virtual threads |
| Memory | `ReadOnlyMemory<byte>` → read-only `ByteBuffer` | JDK standard memory view |
| Certificates | `X509Certificate2` → `KeyStore.PrivateKeyEntry`; .NET TLS enums replaced by small API enums | The JDK separates keys and certificates |
| Reflection | Roslyn code generation replaced by kotlin-reflect (analysis) and method handles (invocation); inline handlers take suspend lambdas or function references | See [Reflection](PORTING.md#reflection) |
| Reflection | Parameter default values are not readable; optional parameters are omitted instead | kotlin-reflect limitation |
| Resources | `FromAssembly` → `fromClasspath` | No assemblies on the JVM |
| Templates | Cottle syntax replaced by Pebble syntax for `Renderer.from(...)` templates | No Cottle implementation on the JVM |
| Glyph11 | Parses contiguous `ByteBuffer`s only (no `ReadOnlySequence` overloads) | The engine always provides a contiguous buffer |
| Glyph11 | The views on the fields of a request parsed from an array-backed buffer are recycled by `BinaryRequest.clear()` (re-pointed to the fields of the next request parsed from the same array) and start at the offset of the field in the input instead of position 0 | Views are objects on the JVM, recycling them keeps parsing allocation-free (`ReadOnlyMemory<byte>` is a struct upstream) |
| API | `IHandlerBuilder<TBuilder>` → `HandlerBuilder.WithConcerns<TBuilder>` | Kotlin cannot overload an interface name by generic arity |
| API | `Forwarding.For` → `Forwarding.forAddress` | `for` is a hard keyword in Kotlin |
| API | `DocumentationAttribute` base class → `@Documentation` meta-annotation; `OperationDocumentation.entries` is a `List<Annotation>` | Kotlin annotations cannot inherit |
| API | `RequestBodyAttribute`, `RequestHeaderAttribute`, `ResponseAttribute`, `ResponseHeaderAttribute` → `@ApiRequestBody`, `@ApiRequestHeader`, `@ApiResponse`, `@ApiResponseHeader` | Avoid clashes with `RequestBody`, `RequestHeader`, `Response` |
| API | Optional annotation parameters use `""` / `Nothing::class` instead of `null`; `ResponseHeaderAttribute.Status` is an array with at most one entry | Annotation parameters cannot be nullable |
| API | `SslProtocols`, `SslPolicyErrors`, `X509RevocationMode`, `CompressionLevel` are small enums in the API; flags become `Set<E>` | No JDK equivalents |
| API | `HttpProtocols` keeps its combined members and gains `hasFlag`, `plus`, `minus` | Replaces `[Flags]` arithmetic |
| API | `ResponseStatus` carries its numeric `code`, `ResponseStatus.fromCode(Int)` replaces casts | Kotlin enums have no implicit integer value |
| API | `IServer.DisposeAsync()` → `suspend fun close()`; `IEndPoint : IDisposable` → `EndPoint : AutoCloseable` | Kotlin lifecycle conventions |
| API | `IPropertyBag.TryGet<T>(key, out T)` → `tryGet(key, KClass<T>): T?` plus a reified `tryGet<T>(key)` extension | No out parameters |
| API | `MemoryView == ReadOnlyMemory` → `contentEquals(ByteBuffer)` | Kotlin `==` only compares with `Any?` |
| API | `MemoryView.copyTo(ByteBuffer)` added | Upstream exposes the memory of a view directly; `bytes` has to return a new buffer on every access, `copyTo` copies the content without creating one |
| API | `SuspendingInput` added (`org.genhttp.api.protocol`): engines serving connections on event loops return it as the stream of `Request.upgrade()` (`dispatcher` of the loop, `readSuspending`) | Upstream reads upgraded connections through a `PipeReader` that can be awaited; the JVM stream blocks, which would halt an event loop |
| Engine | Read timeouts (initial request, keep-alive, TLS handshake) are enforced by a watchdog that checks the deadlines of waiting connections once per second and closes expired connections, instead of a cancellation token per read; timeouts fire up to a second late | A timer per read costs a timer to schedule and cancel on every read, publishing a deadline is a single atomic update; reads block their virtual thread, so they are aborted by closing the connection anyway |
| Engine | The `Date` header is rendered by a background thread at the start of every second instead of checking the clock for every response (like Kestrel does) | Reading the clock costs about 30 ns per response on virtualized hosts |
| Engine | Endpoints with `dualStack = false` on IPv6 accept IPv4 connections at the TCP level but close them immediately | The JDK cannot set `IPV6_V6ONLY`; the binding tests therefore check that a request is answered instead of a bare TCP connect |
| Tests | `ConnectionTests.testUpgrade` reads the 101 response from a raw socket | The JDK HTTP client rejects unexpected 101 responses |
| Tests | `ResourceTreeTests.testByAssembly` checks that the classpath root contains the `Resources` folder instead of exactly one node | The classpath root merges all roots of the runtime, an assembly has a single root |
| Conversion | JSON escapes HTML-sensitive and non-ASCII characters as unicode escapes, enums with explicit values (`ResponseStatus`, `Priority`) are written as their value | Mirrors the defaults of System.Text.Json |
| Conversion | XML element names are written in PascalCase and read case-insensitively; JSON writes whole-number floating point values without fraction (`42`) | Mirrors XmlSerializer (.NET property names) and System.Text.Json |
| Tests | The acceptance tests are friends of selected modules (`friendPaths`) to access internals | Counterpart of `InternalsVisibleTo` |
| Reflection | Kotlin types of lambda parameters are converted with `KType.toJavaType()` (Conversion) | kotlin-reflect cannot map types of lambdas to Java types |
| IO | `FormattableContent<T>` merged into `FormattableContent(value: Any)` (formats via `toString()`, doubles like .NET) | No generic arity overloading, no `IUtf8SpanFormattable` |
| IO | `WritingStream` is a write-only `OutputStream(WritableByteChannel, Flushable)` | JVM streams are not bidirectional |
| IO | Stream checksums require `markSupported()`, `StreamContent.length` is only the known length | JVM streams are not seekable |
| IO | `Handler.From` / `Concern.From` sync and async overloads merged into one suspend lambda | A suspend lambda accepts both |
| IO | `DirectoryContainer` rejects paths that escape the directory (e.g. via `%2F`) | Hardening |
| IO | `ResponseBuilder.apply(modifications)` shadows the stdlib `apply` for response builders | Upstream name kept |
| Websockets | `WebsocketConnection` is not disposable; the `Canceled` frame error is never produced (cancellation throws `CancellationException`); segmented payloads are linearized into a copy | `close()` clashes with the close frame API and the engine owns the input; no `ReadOnlySequence` on the JVM |
| Websockets | Status codes of close frames are `Int` (validated to 0..65535), opcodes are `Byte` | No unsigned types in the public API |
| Websockets | If the upgraded input is a `SuspendingInput` (Netty engine), the message pump runs on its dispatcher (`withContext(input.dispatcher)`) and reads with `readSuspending`; otherwise it reads the blocking stream (`runInterruptible`) as before | Websockets run on the event loop of the Netty engine instead of a virtual thread: an echo costs 5.5 µs of CPU (like the internal engine) instead of 9.0 µs, 16 pipelined echoes 0.53 instead of 0.91 µs each |
| I18n | Overloads of `fromRequest` are resolved by the lambda return type (`@OverloadResolutionByLambdaReturnType`), the culture variant is `fromRequestCultures` on the JVM | Kotlin cannot overload lambdas by return type otherwise |
| I18n | The selected culture is available via `CurrentCulture.culture()` / `uiCulture()` (coroutine context element `CultureContext`) instead of `CultureInfo.CurrentCulture` | The JVM has no per-thread culture; coroutines may switch threads |
| I18n | Language tags without region resolve to a default region (`de` → `de-DE`) using a built-in table | Mirrors `CultureInfo.CreateSpecificCulture` |
| Authentication | Lambda overloads of `authentication(...)` with two parameters need explicit parameter types at the call site | Kotlin does not resolve overloads by the lambda body |
| Authentication | Bearer tokens are `com.nimbusds.jwt.SignedJWT`, keys are `java.security.Key`; unsigned (`alg: none`) and encrypted tokens are rejected | Nimbus JOSE replaces System.IdentityModel; hardening |
| ServerSentEvents | `EventStream` rethrows `CancellationException` instead of sending a retry | Structured concurrency |
| ApiBrowsing | The browser templates (`Index.html`) use Pebble syntax (`{{ title }}`) instead of Cottle | Pebble replaces Cottle (see Pages) |
| LoadBalancing | `PriorityEvaluation` is a typealias `(Request) -> Priority` | Delegates map to function types |
| Engine | Implementation clashes in Engine/Shared: `ServerHost` → `AbstractServerHost`, `ClientConnection` → `RemoteClientConnection`, `KeyValueList` → `GlyphKeyValueList`, `PropertyBag` → `MapPropertyBag` | The API interfaces use these names (`I` prefix dropped) |
| Engine | Engine/Shared offers extension points for the Netty engine that upstream does not need: `WriteTarget` (the buffers a `ConnectionWriter` collects data in and how they are sent; the internal engine keeps pooled direct buffers written to its channel), `ConnectionReader.reset()` and `ConnectionReader.capacity` (reuse of pooled readers, grown ones are not pooled) and an overridable `ConnectionReader.asInputStream()` (the upgraded stream) | Upstream engines share `PipeReader`/`PipeWriter`, which already provide engine-owned buffers and awaitable reads |
| Files | `FileAssetsBuilder.refreshInterval(...)` is accepted but has no effect | Upstream it only affects the native file path of the Ioxide engine (`ioxide.file`), which ioxide's Kotlin port does not have yet |
| DependencyInjection | Koin replaces Microsoft.Extensions.DependencyInjection (`IServiceProvider` → `Koin`, `IServiceScope` → `Scope`); scoped services are registered in `scope(RequestScope) { scoped { } }`; `ActivatorUtilities` is replaced by an internal activator (primary constructor, parameters resolved by class) | See [specs/dependency-injection.md](specs/dependency-injection.md) |
| Tests | `IoxideFilesTests` and the tests of `Engine/Ioxide` (certificates per host and rotation, HTTP/2 and HTTP/3 streams, `Http1WriterStream`, engine options of QUIC) are not ported; `additional/ioxide` tests the engine instead | They test the native file path (`ioxide.file`), certificate features of BoringSSL and protocols that ioxide's Kotlin port does not have yet, or types the port does not have (the writer stream is the `ConnectionWriter` of `Engine/Shared`) |
| ReverseProxy | The JDK `HttpClient` replaces `HttpClient`/`SocketsHttpHandler`: `adjustHandler` takes `(HttpClient.Builder) -> Unit`, `adjustClient` runs on the built client; the read timeout is applied per request (`readTimeout` parameter on `ReverseProxyProvider`/`HttpProxy`) | The JDK client is immutable and has no handler type |
| ReverseProxy | `Expect`, `Transfer-Encoding` and `Content-Length` request headers are not copied (the body framing is derived from the body publisher); the JDK client adds a `User-Agent` if the client sent none | Restricted headers of the JDK client |
| ReverseProxy | `WebsocketTunnelContent` takes the request as a second argument; `DuplexPipe` wraps a socket's streams; the tunnel ends when either direction ends | The client side of the tunnel is read from `request.upgrade()`; no System.IO.Pipelines |
| ReverseProxy | Upstream status codes unknown to `ResponseStatus` are answered with 502; `Content-*` request headers are matched case-insensitively | Avoids invalid responses / 500s for lower-case headers |
